    Fuel-optimal landing, solved live in your browser

    The guidance is the same idea used for reusable boosters and Mars landers: turn the landing into a convex optimisation problem, which can be solved fast and reliably on board, then solve it again and again as the vehicle drifts.

    The problem it solves

    Given where the booster is and how fast it is moving, find the thrust at each of 30 time steps that lands it on the pad at zero speed using the least propellant. The engine cannot throttle below 40%, so the true problem is not convex. A standard trick called lossless convexification adds a slack variable σ for the thrust size; the relaxed problem is convex, and its optimum provably sits on the real limits.

    minimise Σ σₖ Δt propellant subject to exact dynamics with gravity r_N = pad, v_N = 0 ‖aₖ‖ ≤ σₖ thrust size, relaxed T_min/m ≤ σₖ ≤ T_max/m throttle limits tilt(aₖ) ≤ 26° engine pointing height ≥ tan 20° × range glide slope

    The solver

    There is no optimisation library here. The page carries its own conic solver, written from scratch: the trajectory is folded into 120 thrust variables, every constraint becomes a projection onto a cone or a box, and an ADMM loop (the method behind the OSQP solver) alternates between one cached linear solve and those projections. It retunes its step size as it goes. The flight time is not known in advance, so the opening plan runs a golden-section search over it, about 18 solves.

    Flying it

    The plan runs in a background worker while the 120 Hz flight model keeps going. The vehicle follows the plan with a feedback tracker; about every second the planner re-solves from the current state, keeping the same touchdown time if it can and slipping it a little if not. When wind, a shove or an engine fault knocks it off course, the next solve absorbs it. If no safe landing exists, the solver reports that instead of pretending.

    Other vehicles and worlds

    The same guidance flies a small test hopper, a Mars lander in thin air and a lunar lander in vacuum. Gravity, air density and the vehicle's mass, thrust range and engine efficiency all feed straight into the problem, so you can type in your own vehicle and see whether it can land at all.

    Reliability testing

    One good landing proves little. The Reliability view flies a scenario dozens or hundreds of times with random start states, wind, gusts and engine faults, each one a full flight with the planner in the loop, and reports how many land, how hard and how far from centre. When a plan is impossible with the normal thrust reserve the planner tries again using nearly all the thrust there is; if that also fails it brakes as hard as it can.

    What is simplified

    A point-mass vehicle with ideal attitude control, one engine, a simple drag model for wind, and flat ground. Mass loss is handled by successive approximation inside each solve.
